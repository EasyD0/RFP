## 4. 实现细节 · 算法

总原则（贯穿所有算法）：**无虚警保证**。每个判定必须落在三种可验证依据之一——形式固定的代码模式（正则）、可判定的语法/语义属性（libclang AST）、或可靠的外部符号信息（clangd 跨 TU 引用）；证明不了就保守不判，绝不冒险把真缺陷标成误报。

各规则的判定链、技术依赖与参数要求如下：

| 规则 | 判定链（子算法按序，命中即短路） | 技术依赖 | 参数完整性的要求 |
| --- | --- | --- | --- |
| **69D** 变量未赋值就使用 | ① 声明处显式初始化 → ② 全局/静态零初始化 → ③ 中途初始化（同一层级）→ ④ 仅取地址使用 | 正则 + libclang | ③④ 需要编译参数才能解析 AST；①② 可纯文本 |
| **57S** 无作用语句 | ① 宏占位/`(void)` 置空 → ② 日志打印 → ③ 汇编 → ④ 声明语句 → ⑤ 函数调用 | 正则 + libclang | ④⑤ 需 libclang；①②③ 可纯文本 |
| **1X** 声明类型不一致 | ① 代码行不足两处 → ② 语义一致比较（storage/linkage/canonical type） | libclang | ② 必须有可靠编译参数（前提 clang 解析正确） |
| **47S** 数组越界 | 常量下标界内 → 判误报；变量下标 → 单层约束分析，可证界内才判 | libclang | 需要完整下标 AST 与数组长度信息 |
| **36S** 函数无返回语句 | 定位全部引用 → 逐一验证是否使用返回值（libclang 检查 CallExpr 父节点） | clangd + libclang | **必须**有 clangd + compile_commands.json |
| **132S** 逻辑表达式使用赋值 | 收集赋值 → 沿父链判断消费方式（比较=取值 / `&&`=`布尔`） | libclang | 需 AST 父链 |
| **404S** 字符串数组越界初始化 | 纯文本算法与 libclang 算法**并行**，任一命中判误报 | 正则(状态机) + libclang | 纯文本无需外部依赖；libclang 分支需 AST+诊断 |

### 4.1 代表性算法的"保守近似"设计

- **47S 数组越界**：把"是否越界"（对任意 C 程序不可判定，归约到停机问题 / Rice 定理）降为**只对编译期可判断界**的情形判定。常量下标（字面量/枚举/简单宏）用值提取；变量下标用 `get_constraint` 提取 for/while/if 的单层约束，满足 `0 ≤ idx < arr_size` 才判误报；约束区域内下标被改写、或含复杂表达式 / 跨行 / `||` / 函数调用时一律保守不判。
- **69D 中途初始化**：理想需追踪所有可达路径上的初始化集，这同样不可判定。退行实现为**只检查与引用同一语法层级、且位于其前的初始化/取地址**语句；找不到证据则保守不判、不抛异常。
- **36S**：用 clangd 拿到的是**全部编译单元**的引用，而非单文件；再叠加 libclang AST 对每个调用点的父节点做二次校验（`CompoundStmt` / `(void)` 强转 / 无大括号控制流体判定为"不使用返回值"），用"引用定位 + AST 验证"双层保证不虚警。
- **404S**：纯文本算法用状态机准确切分数组定义语句（跳过注释/字符串/嵌套花括号），并把 `#include` 原位展开统计各维元素；文本无法判别（如宏定义维度）时回退到 libclang，用类型大小 + `excess elements in array initializer` 诊断交叉校验。

## 5. 实现细节 · 软件工程

### 5.1 非侵入式装饰器：子算法的"声明式注册"与"独立开关"

每个规则是一个独立的 `Checker` 子类，其子算法只是**带装饰器的方法**（`tag_padding` / `common_method` / `un_used`），规则的判定链由装饰器在注册期自动收集，而不是手写在 `do()` 里。这样子算法与规则的控制流完全解耦：

- `@register_checker(rule_code, rule_name)`：在类注册时注入 `rule_code`，扫描类内方法，凡带 `tag_padding` / `common_method` 标记的自动加入 `_ProcessListAll` / `_ProcessListCommon`（按方法名排序，顺序稳定）。
- `@tag_padding("<...>")`：把一个方法标记为**子算法**；判定命中误报后自动把该 tag 追加到问题描述（可审计、可追溯"为什么判误报"）。
- `@common_method`：标记为**通用子算法**（额外进 `_ProcessListCommon`）。
- `@un_used`：标记为**暂不启用**，注册时被剔除，换算法不需要改规则类。
- `Checker.do()`：按序执行成员方法，**一旦判为误报立即短路**（命中即止，符合"判了必对、停止后续"的语义）。

**参数的完整性决定开关**——这正是"非侵入式开关"的落点：子算法各自声明外部依赖（正则 / libclang / clangd / 纯逻辑），而这些依赖的可获得性由参数完整性决定（是否有可靠编译参数、是否有 clangd、是否有 compile_commands.json）。因此：

- 参数完整时，规则可启用 libclang / clangd 的高能力子算法；
- 参数缺失时（如无 clangd），可只保留纯文本子算法，规则**降级运行**而非整体失效。

由于开关作用在**独立的方法装饰器**上、与规则类结构无关，增减子算法、按环境切换能力集都不侵入规则主体——这就是"非侵入式"的核心收益：**算法与能力分级解耦，同一份规则在多套参数完整度下都能以最低可用能力运行并保持无虚警**。

### 5.2 通用检查

`Checker_isUsed`（"未参与编译文件 → 误报"）设计上附加到每条规则，通过 `common_method` 进入通用列表；它复用 CodeContext 提供的参与编译文件集合。当前调用路径下该检查处于待启用状态（见《说明.md》2.4）。

### 5.3 多进程调度与编译上下文

- `runner.py`：`total_check`（串行，便于调试）与 `total_check_parallel`（多进程）。worker 通过 `initializer` 反序列化**父进程已构建好的 CodeContext**，不重复执行 `__init__`——因此不会重复初始化 `Preprocessor`、不会重写 `.resp` / `compile_commands.json`，**无文件竞态**；每个 `problem` 作为一个任务分发，`Pool` 退出后 `kill_all_clangd_processes()` 兜底清理 worker 里可能变孤儿的 clangd 进程。
- `context.py` `CodeContext`：统一负责初始化 Preprocessor、生成 `compile_commands.json`（供 clangd / libclang 使用）、提供 `get_args` 编译参数与参与编译文件集合；整体可 pickle，是"多进程不重复初始化"和"参数完整性判定"的共同基础。

## 6. 后续计划

### 6.1 调研用户：未识别且未采纳的问题要做什么

上线后，除了"被我们识别为误报、但用户仍可能需要确认"的问题，更值得关注的是**未被识别、但最终用户也不采纳**的问题——这些是判定的盲区，也是提升识别率的机会。

- **目标**：区分"识别能力不足（我们漏了）"与"真命题但用户不关心（无需处理）"，据此决定把算力投到哪类子算法上。
- **做法**：对给出"不采纳"结论但未被识别的问题抽样，按（规则 × 形态）归类，反哺到对应规则的子算法增强或新子算法设计。

### 6.2 把"函数是否被调用"引入其他规则

一些问题（如无作用语句、缺返回、未用变量等）在**该函数未被任何地方调用/不受关注**时，优先级可进一步降低甚至判定误报更可靠。计划把"函数是否被调用"作为一条可复用的判定前提。

- **惰性方案**：不为所有问题常驻建立调用索引，而是**仅在确实存在 2D / 36S 等规则问题、有建立索引必要时**，才对所有违规问题检查其所在函数是否被调用、被谁调用。避免无谓的全量索引开销。
- **难点——入口函数的识别**：调用图中存在根节点（`main` / 中断 / OS 回调等入口函数）。**入口无调用者**，若用"无调用者 → 该函数不被关注"的启发，会误伤真实入口。如何形式化识别入口函数（脚本 / 符号表 / 链接规则），只在**完整工程**的上下文里讨论才有意义，因此列为后续专项。

### 6.3 数组越界的判定优化

现状：47S 只检查**单层约束**，能力太弱，导致对很多"有防护但防护跨多层"的问题识别不出，几乎失去识别无效问题的能力。

后续考虑（保持**无虚警**前提下逐步放开）：

- **多层约束组合**：把外层嵌套结构（外层 `for`/`while`/`if` 的约束）传进内层访问点合并，形成更强的边界证据；当前单层是它的保守子集。
- **边界传播与常量折叠**：对 `i = C` → 递进 `i++/i--` → 比较 `i < N` 这一条链做系统化传播，支持上下界区间而不是单点。
- **约束运算符增强**：扩展 `==` / `!=` / 区间判断，并在约束区域内有下标改写时精确判定失效区间（现在是一刀切不判）。
- **利用 clangd 全量引用**：把"数组在本编译单元之外是否被写入/其大小是否被外部定义"纳入判断，扩大可判范围。
- **可靠性保证**：每一类新增判定都要能给形式的正确性论证（或至少：可证明界内才判，证明不了仍保守），确保新增覆盖面不引入虚警。
